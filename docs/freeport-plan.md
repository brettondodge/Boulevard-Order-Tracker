# Freeport Billing — Rebuild Plan

Status: **in progress** — steps 1–5 done. This replaced most of the first
Freeport build; the Tools dashboard and login stayed.

## The problem

Boulevard Glass is on call 24/7 for Freeport-McMoRan (Safford). Jobs happen all
month; the office manager writes invoices when she has time. By month-end,
Freeport needs every job for that month billed as **one** consolidated package,
and they write one check against it.

We are moving invoicing from ELMO to **Omega**. Omega handles real billing,
accounting, payment batching and balancing. Two Omega limits drive this app:

1. **Invoice dates can't be changed.** A job installed Sept 29 but invoiced
   Oct 15 is dated October in Omega. Freeport wants it in September, and would
   object to an October-dated invoice in the September package.
2. **We don't want an open "consolidated" invoice in Omega.**

## What the app is

A **records manager for Freeport billing** that replaces the Google Sheet the
office manager fills in at month-end. It holds a copy of each Freeport invoice's
data (imported from Omega), groups invoices by **install date**, and produces the
three month-end deliverables. It is not an accounting system and never posts to
Omega.

Users: mainly the office manager; Bretton and admins can view everything.
Freeport Billing is **computer-only**: on phones the dashboard shows just the
Order Tracker, and the home-screen app opens the dashboard.

**Freeport is still invoiced in ELMO** until everything moves to Omega, so
invoices are entered by hand for now (labels say "Invoice #", not "Omega").
October 2026 runs in parallel: the usual Google Sheet plus the app, compared
before any app-made file goes to Freeport.

## Month-end deliverables

1. **Merged invoice PDF** — every invoice for the month. The app generates its own
   one-page copy of each invoice (Omega invoice #, install date, order number,
   account, line items, tax, total) and merges them, so Omega's invoice date never
   appears in the wrong month. *(Plan B — chosen. Plan A, invoicing in Omega
   before month-end, is encouraged when possible but not relied on.)*
2. **Consolidated invoice PDF** — the one Freeport pays. Generated by the app:
   - Bill To: Freeport McMoRan - Safford, Accounts Payable, P.O. Box 25109,
     Phoenix, AZ 85002-5109
   - PO **ZD00000669**, Contract No. **33282200158-001**, "Attn: September 2026"
   - Invoice number **FMI-YYYY-MM** (corrections: **FMI-YYYY-MM-R1**, R2…)
   - Line items: **Total Parts**, **Total Labor**; Subtotal; **Tax 9.1% of parts
     only**; Invoice Total
   - Business info, remit-to, AZ ROC#, AZ Procure Vendor ID, late-fee line —
     the same information as past invoice 10239376, which Freeport accepted
   - Layout: a clean version of past invoice 10239376, without the auto-glass
     insurance/vehicle/signature sections.
3. **Line-item spreadsheet (.xlsx)** — replaces the Google Sheet. One row per
   invoice line, same 15 columns as the existing sheet:

   | Column | Source |
   |---|---|
   | DESCRIPTION | Item master list |
   | Classification | blank |
   | QUANTITY | Invoice line |
   | UNIT OF MEASURE | Item master list (ea / hr) |
   | UNIT RATE | Invoice line (as billed) |
   | TYPE | always "Work Order" |
   | COMPANY CODE | always 1328 |
   | ORDER NUMBER | Omega "ORDER NO." field — unique per job |
   | WBS ELEMENT | blank |
   | ACCOUNT CODE | Chosen per invoice (location list below) |
   | Cash Pay | blank |
   | EXPENSE ELEMENT | From item type: Parts 61040078 / Labor 61120032 |
   | SUPPLIER REFERENCE | Omega invoice number |
   | USING AREA NAME | Per account code; all start as "Mine Maintenance" |
   | PO NUMBER | always **ZD00000669** |

   Labor stays **one row per technician** (two techs = two identical rows).
   The same rows are viewable in the app; the .xlsx is what gets emailed.

## Key rules

- **Billing month = install date** (Omega's Scheduled Date), not invoice date.
  The office manager can override it per invoice.
- **Tax = 9.1% of the month's total parts**, matching past consolidated invoices.
  The app also shows the sum of per-invoice Omega tax so a rounding difference
  is visible, not hidden.
- **Billed prices are never changed by the app.** Master-list prices only flag
  mismatches.
- **Only master-list items are allowed.** Anything unknown is flagged for review.
- Once a month is marked **Sent** it's locked. Corrections create a new revision
  (R1, R2…) and the previous version is kept.

### Dates and imports

The import date range never decides the billing month. The import only brings
invoices in; the app sorts them by install date.

- **No duplicates.** One record per Omega invoice number. Re-importing updates an
  unsent invoice and never creates a copy, so overlapping ranges are safe.
  Habit: import "first of last month through today".
- **Freeport only.** Imports keep only the Freeport McMoRan - Safford account.
- **Late invoice for a sent month** → never added silently. It's flagged and goes
  out as a correction (R1) of that month, so Freeport's records match ours.
  (Billing it in the next month was rejected for that reason.)
- **Date flags:** missing install date (blocks Ready); install date after the
  invoice date; install date more than ~30 days before the invoice date.
- **Missing-invoice check** (if the Omega API supports it): Month close warns
  about Freeport jobs scheduled that month but not yet invoiced.

### Month-end process

- Office rule: **all Freeport jobs are invoiced in Omega before month-end.**
- Boulevard sets the billing cycle and has **45 days** to submit. A month stays
  Open until someone closes it; closing a few days into the next month (e.g. by
  the 5th) lets last-day jobs land in the right package and keeps corrections rare.

## Data

### Invoice record
Omega invoice #, Omega invoice date (kept as-is), install date, billing month,
order number, account code, line items, Omega tax, Omega total, status
(**Needs review → Ready**), optional Google Drive folder link, notes.

### Item master list (admin-editable form)
Per item: Omega SKU, description for Freeport's sheet, unit (ea/hr),
Parts/Labor (sets expense element and taxability), standard price, active flag.

**Per-line description items** (Windshield, Special-order part, Freight / crating)
cover one-off parts: the description (e.g. "DW02153GTYN Windshield") and price are
typed on each invoice line and go into the spreadsheet as typed. A blank list price
means the price is always entered per line.

The starting list comes from the January–September 2026 billing sheet: 15
fixed-price items billed every month plus those three per-line items. Spelling and
unit inconsistencies in the old sheet (e.g. "Tech Labor - Over Time", overtime
billed as "ea") are standardized.

Each glass size has its own SKU in Omega (e.g. "24 x 48 (.090 Clr Lami)"),
so lines match **by SKU**. Until Omega is updated, a SKU that still covers
several sizes falls back to matching **by price**; if that fails, the office
manager picks during review.

## Screens

| Screen | Purpose |
|---|---|
| **Month view** (Freeport home) | Pick a month. List of its invoices: invoice #, install date, order #, account, parts, labor, tax, total, status. Month totals on top. Import and Add buttons. |
| **Invoice record** | Header fields + line items + review flags. Mark Ready. |
| **Month close** | Preview the three deliverables, download each, mark Sent, start a revision. |
| **Admin** | Item master list, account codes, settings — all normal forms. |

## Not doing (for now)

- Posting anything to Omega or QuickBooks, payments, emailing Freeport.
- Storing work orders and photos in the app — they stay in Google Drive.
  A later phase could upload through the app and file them into Drive automatically.
- Reading Omega invoice PDFs as a data source.
- From the first build, dropping: PDF text parser, import conflict handling,
  advisory locks, time-coverage panel, JSON settings editor, allocation JSON.

## Build order

Each step is a small commit you can look at before the next.

1. ✅ **Shell** — the four screens with sample data, navigation, no saving. Remove
   the first build's Freeport code (the dashboard and login stay).
2. ✅ **Records** — save invoices, line items, item master list, account codes,
   settings. Manual entry. Staff edit invoices; items, account codes and settings
   need the existing admin unlock (same as Master Lists).
3. ✅ **Spreadsheet export** — the 15-column .xlsx, one sheet named like the
   Google Sheet tabs ("September 2026"); code columns are numbers. Downloads only
   once every invoice in the month is Ready.
4. ✅ **Consolidated invoice PDF** — one page: FMI number, month-end date, PO,
   contract, "Attn: Month Year", Parts / Labor / Subtotal / Tax / Total, ROC#,
   Vendor ID and footer note.
5. ✅ **Merged invoice PDF** — one app-made page per invoice in install-date
   order, showing the install date (not the invoice date), order #, account,
   lines and totals; long invoices continue onto extra pages.
6. **Month close** — Sent lock and revisions.
7. **Omega import** — preferably through the **Omega API**
   (https://app.omegaedi.com/api/docs/): API key auth, `GET /Invoices` with
   date filters, CSV export, combined-PDF print, and an event webhook that
   could pull new Freeport invoices automatically. First, a test call to confirm
   it returns line items, scheduled date and the ORDER NO. custom field (the
   docs don't show them). If it doesn't, fall back to the ItemsReportDrilldown
   .xlsx plus entering the missing fields. Either way: match SKUs to the master
   list and flag anything unknown. The API key lives in local `.env` / hosting
   secrets only. The app reads from Omega; it never changes Omega invoices.
8. *Later:* Google Drive uploads for work orders and photos.

## Resolved questions

1. **Own SKU per glass size?** Yes — Omega SKUs will be renamed per size.
2. **Where do install date, ORDER NO., description and UOM come from?** All are
   on the Omega invoice; Omega also has an API (see step 7).
3. **USING AREA NAME for non-Mine accounts?** Stays "Mine Maintenance" for now;
   stored per account so it can change without code.
4. **Consolidated invoice wording?** Not confirmed with Freeport; mirror the
   accepted past invoice 10239376, minus the auto-glass sections.
5. **Which bulk-print PDFs are Freeport invoices?** Deferred — not needed yet.
